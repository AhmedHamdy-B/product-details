Pattern: Query Key Factory (TanStack Query)

Pattern Name: Query Key Factory
Docs: TanStack Query Keys

Instead of using inline arrays across files, query keys are centralized in one factory. This makes invalidation and cache consistency predictable.

Wrong (No Key Factory)

// scattered across app
useQuery({
  queryKey: ['easyorders-product', slug],
  queryFn: () => fetchProductBySlug(slug),
})

// somewhere else typo/inconsistency
queryClient.invalidateQueries({
  queryKey: ['easy-order-product', slug], // typo bug
})

Right (Key Factory Applied)

// src/api/product.keys.ts
export const productKeys = {
  all: ['product'] as const,
  detail: (slug: string) => [...productKeys.all, 'detail', slug] as const,
}

// src/pages/ProductDetailPage.tsx
const productQuery = useQuery(productDetailQuery(slug));

// anywhere else
queryClient.invalidateQueries({
  queryKey: productKeys.detail(slug),
})
Pattern: Atomic Selector + Shallow Selection (Zustand)

Pattern Name: Atomic Selector Pattern
Docs: Zustand useShallow guide

Components subscribe only to the exact state they need. Grouping with useShallow prevents unnecessary rerenders when other store fields change.

Wrong (Broad / Multiple Subscriptions)

// broad subscribe can rerender too often
const store = useCartStore();
const count = store.getUniqueCount();

// or many independent subscriptions in one component
const lines = useCartStore((s) => s.lines);
const openDrawer = useCartStore((s) => s.openDrawer);

Right (Atomic + useShallow)

// src/components/SiteHeader.tsx
const { basketCount, openBasket } = useCartStore(
  useShallow((state) => ({
    basketCount: state.lines.reduce((sum, line) => sum + line.quantity, 0),
    openBasket: state.openDrawer,
  })),
);
Pattern: Route-Level Code Splitting (React Router lazy)

Pattern Name: Code-Splitting with Lazy Routes
Docs: React Router lazy routes

Pages are loaded on demand via route lazy, reducing initial bundle size and improving startup performance.

Wrong (Eager Imports)

// App.tsx
import { ProductDetailPage } from './pages/ProductDetailPage'
import { TestingReferencePage } from './pages/TestingReferencePage'

<Routes>
  <Route path="/" element={<ProductDetailPage />} />
  <Route path="/testing" element={<TestingReferencePage />} />
</Routes>

Right (Lazy Routes)

// src/router.tsx
{
  path: 'testing',
  lazy: async () => {
    const { TestingReferencePage } = await import('./pages/TestingReferencePage')
    return { Component: TestingReferencePage }
  },
}
Pattern: CVA Variant Schema (Design System Styling)

Pattern Name: Class Variance Authority (CVA)
Docs: CVA Documentation

Styling decisions (intent, size, shape, weight) are encoded in a typed variant schema instead of spread nested class conditions inside JSX.

Wrong (Repeated Inline Class Strings)

// repeated in many files
<button className="min-h-[58px] rounded-md bg-black text-white ..." />
<button className="min-h-[58px] rounded-md border bg-white text-black ..." />
<button className="px-16 py-4 rounded-full bg-black text-white ..." />

Right (CVA Variants)

// src/components/ui/Button.tsx
const buttonVariants = cva('inline-flex items-center justify-center', {
  variants: {
    intent: { primary: 'bg-black text-white', secondary: 'border bg-white text-black' },
    size: { md: 'min-h-[58px] px-5', sm: 'px-16 py-4' },
  },
  defaultVariants: { intent: 'primary', size: 'md' },
})

// usage
<Button intent="secondary" weight="medium">Checkout Now</Button>
Pattern: Type-Safe i18n Resource Augmentation

Pattern Name: i18next Resource Augmentation
Docs: i18next TypeScript support

i18next types are augmented with your resource shape so translation keys are validated at compile-time.

Wrong (Raw String Keys Everywhere)

// typo passes silently until runtime
t('toats.addedTitle')
t('header.saveditems')
// missing key may render blank/fallback in production

Right (Augmented Resource Typing)

// src/i18n/i18next.d.ts
declare module 'i18next' {
  interface CustomTypeOptions {
    defaultNS: 'translation'
    resources: { translation: typeof messagesEn }
  }
}

// now typed usage catches key mistakes during development
Refinement: React Query Owns Server State

What was improved: Removed duplicated server state ownership between React Query and Zustand.
Applied in: src/pages/ProductDetailPage.tsx, src/stores/productStore.ts

Product API data now lives in React Query only. Zustand is focused on UI state (selection behavior), which prevents stale sync bugs and reduces complexity.

Before (Dual Source of Truth)

// query fetches data, then page ingests into store
if (productQuery.data) ingestProduct(productQuery.data)
if (productQuery.isError) ingestError(message)
if (productQuery.isPending) setLoadingFlag(true)

After (Single Owner)

const productQuery = useQuery(productDetailQuery(slug))
const product = productQuery.data ?? null
const loading = productQuery.isPending
const errorMessage = productQuery.isError ? readableError : null

What was improved: Stable cart matching logic and safer persisted-store upgrades.

Cart line merge now uses normalized selections instead of object stringify order. Persisted stores now include version + migrate to stay robust across schema changes.

Refinement: Rich Text Best Practices (Typography + CVA + Sanitization)

What was improved: Replaced brittle rich-text styling and secured HTML rendering.
Applied in: src/components/ProductBuyingSection.tsx

Rich description now uses Tailwind Typography (prose), CVA for expanded state, semantic article, and DOMPurify sanitization before rendering HTML.

Before

const descriptionCopyClass = "... long [&_tag] chain ..."
<div className={cn(descriptionCopyClass, !expanded && 'line-clamp-4')}
     dangerouslySetInnerHTML={{ __html: html }} />

After

const descriptionVariants = cva('prose prose-neutral max-w-none ...', {
  variants: { expanded: { true: '', false: 'line-clamp-4' } }
})
const sanitizedHtml = DOMPurify.sanitize(html, { USE_PROFILES: { html: true } })

<article className={descriptionVariants({ expanded })}
         dangerouslySetInnerHTML={{ __html: sanitizedHtml }} />
